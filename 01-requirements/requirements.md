# Требования к подсистеме мониторинга рейсов TravelTech

## Допущения

1. TravelTech уже поддерживает путешествия, бронирования и совместный доступ к плану поездки.
2. Мониторингу подлежат рейсы, добавленные в путешествие и однозначно идентифицированные.
3. Данные о рейсах поступают из внешних API и/или поддерживаемых уведомлений авиакомпаний. Доступность и частота обновления зависят от поставщиков.
4. Система предлагает альтернативы, но оформляет новое бронирование только после подтверждения пользователя.
5. Проверка визовых ограничений возможна при наличии данных о путешественнике и актуальных правил. Если проверить ограничение нельзя, система предупреждает об этом.
6. Паспортные данные собираются только при необходимости и удаляются после достижения цели обработки, если закон не требует иного.

## Функциональные требования (ФТ)

| ID | Требование |
|---|---|
| ФТ-01 | Система должна добавлять подтверждённые рейсы из бронирований путешествия в мониторинг. |
| ФТ-02 | Система должна идентифицировать рейс по авиакомпании, номеру, дате и аэропортам отправления и прибытия. |
| ФТ-03 | Система должна получать статусы и изменения расписания рейсов из внешних источников. |
| ФТ-04 | Система должна сохранять статус рейса, источник данных и время обновления и получения данных. |
| ФТ-05 | Система должна выявлять задержки, отмены и изменения расписания; повторные события не должны обрабатываться повторно. |
| ФТ-06 | Система должна показывать время последнего обновления и предупреждать об устаревших данных. |
| ФТ-07 | При изменении рейса система должна проверять влияние на пересадки, другие рейсы, трансферы, отели и активности. |
| ФТ-08 | Система должна проверять возможность пересадки с учётом времени между рейсами, аэропортов и минимального времени пересадки. |
| ФТ-09 | При отмене рейса или риске пропуска пересадки система должна искать альтернативные маршруты. |
| ФТ-10 | При подборе альтернатив система должна учитывать условия провоза багажа и указывать различия. |
| ФТ-11 | При подборе альтернатив система должна учитывать гражданство, визы и транзитные требования; непроверенные ограничения должны отмечаться. |
| ФТ-12 | Система должна рассчитывать и отображать время рейсов и пересадок с учётом часовых поясов аэропортов. |
| ФТ-13 | Система должна показывать параметры альтернатив: время, длительность, пересадки, стоимость и условия багажа, если данные доступны. |
| ФТ-14 | Если изменение рейса конфликтует с активностью, система должна отметить конфликт и предложить замену при наличии вариантов. |
| ФТ-15 | Система должна обновлять общий план поездки и уведомлять затронутых участников об изменениях. |
| ФТ-16 | Система должна сохранять уведомления и изменения на сервере, чтобы пользователь получил их после восстановления соединения. |
| ФТ-17 | Пользователь должен иметь возможность выбрать или отклонить альтернативу. Новое бронирование выполняется только после подтверждения пользователя. |
| ФТ-18 | Система должна предоставлять доступ к общему плану и действиям с бронированиями согласно правам участников поездки. |
| ФТ-19 | Система должна уведомлять пользователей о нарушении рейса, доступности альтернативных вариантов и успешном обновлении плана поездки. |


## Нефункциональные требования (НФТ)

| ID | Требование |
|---|---|
| НФТ-01 | 95% обновлений должны обрабатываться не позднее чем через **[X] секунд** после получения данных системой. Задержка публикации данных внешним источником не учитывается. |
| НФТ-02 | Порог актуальности данных должен настраиваться; при его превышении система должна показывать предупреждение и время последнего обновления. |
| НФТ-03 | При недоступности внешнего источника система должна сохранять последний статус, не считать ошибку признаком задержки или отмены и повторять запросы после сбоя. |
| НФТ-04 | После восстановления соединения приложение должно синхронизировать план поездки и непрочитанные уведомления не позднее чем за **[X] секунд** в 95% случаев при стабильном соединении. |
| НФТ-05 | Доступ к данным поездки и персональным данным должен предоставляться только авторизованным пользователям и компонентам с соответствующими правами. Передача данных должна быть защищена. |
| НФТ-06 | Паспортные данные должны храниться в защищённом виде и автоматически удаляться после прекращения цели обработки, если нет законного основания для дальнейшего хранения. |
| НФТ-07 | Моменты времени должны храниться в однозначном формате; расчёты и отображение расписания должны учитывать часовые пояса и переходы на летнее/зимнее время. |
| НФТ-08 | Система должна соблюдать ограничения внешних API и учитывать указания поставщика при повторных запросах. |
