## Функциональные требования

| ID | Функциональное требование | Критерии приемки |
| :--- | :--- | :--- |
| **FR-001** | **Отслеживание статуса рейса** | Система регулярно запрашивает данные у авиакомпаний. Если рейс задерживается или отменяется, система фиксирует это изменение. |
| **FR-002** | **Проверка актуальности данных** | Система показывает время последнего обновления статуса. Если данные пришли с задержкой или противоречат другим источникам, система перепроверяет статус рейса, прежде чем отправить пользователю уведомление об отмене или задержке. |
| **FR-003** | **Уведомление пользователя (онлайн и оффлайн)** | При изменении рейса система отправляет Push или SMS. Если пользователь оффлайн, уведомление сохраняется в личном кабинете и показывается при следующем входе. |
| **FR-004** | **Многопользовательский режим** | В поездке есть роли «Организатор» и «Участник». Уведомления получают все. Подтвердить покупку нового билета может только Организатор. |
| **FR-005** | **Подбор альтернативных рейсов** | При отмене рейса система показывает до 3 альтернативных варианта перелета с указанием времени и цены. |
| **FR-006** | **Проверка ограничений для альтернатив** | При показе альтернатив система проверяет: хватает ли времени на пересадку с учетом часовых поясов, подходит ли тариф по багажу, нужна ли виза для новых транзитных стран. |
| **FR-007** | **Обновление общего плана поездки** | Если рейс изменился, система предупреждает пользователя, что старый трансфер и отель больше не подходят по времени, и обновляет общий маршрут после выбора нового рейса. |
| **FR-008** | **Удаление паспортных данных** | После завершения поездки система автоматически удаляет паспортные данные пользователей, чтобы они не хранились дольше необходимого. |
