### UC-001. Отслеживание статуса рейса

**Название:** Отслеживание статуса рейса

**Акторы:** Система / Провайдер статусов рейсов

**Предусловие:** 
У пользователя есть оформленная и оплаченная поездка с активным авиарейсом.

**Основной сценарий:**
1. Внешний сервис присылает новые данные о рейсе (или система сама их запрашивает).
2. Система проверяет актуальность данных (не пришли ли они с большой задержкой).
3. Система фиксирует новый статус рейса:
   * Если статус «Без изменений» — сценарий завершается.
   * Если статус «Задержан» или «Отменен» — переходим к шагу 4.
4. Система обновляет общий план поездки (помечает связанные события как «Требующие внимания»).
5. Система инициирует отправку уведомления пользователям (переход к UC-002).

**Альтернативный сценарий:**
* **А1. Данные пришли с задержкой (шаг 2):**
1. Система видит, что данные обновились слишком поздно.
2. Система не отправляет пользователю уведомление сразу, а запрашивает подтверждение статуса у альтернативного источника (например, через API авиакомпании).
3. Если статус подтвердился — система фиксирует изменение и переходит к основному сценарию. Если нет — игнорируем событие.

**Исключения:**
* **Сайт авиакомпании не отвечает:** Система не может получить новый статус. Пользователь видит на экране последнюю сохраненную информацию с пометкой «Данные могут быть неактуальны».

### UC-002. Получение уведомления об изменении рейса

**Название:** Получение уведомления об изменении рейса

**Акторы:** 
* Система 
* Участник / Организатор

**Предусловие:**
* У пользователя есть актуальный рейс.
* Обновилась информация о рейсе (после выполнения UC-001).

**Основной сценарий:**
1. Система формирует текст уведомления (например, «Рейс отменен. Мы подобрали для вас альтернативы»).
2. Система отправляет Push-уведомление через сервис доставки.
3. Пользователь получает Push-уведомление на экран телефона.

**Альтернативный сценарий:**
* **А1. Пользователь оффлайн (шаг 2):**
1. Сервис доставки сообщает, что Push-уведомление не доставлено.
2. Сервис доставки ставит Push в очередь на отправку.
3. Система дополнительно сохраняет уведомление в базу данных (в «Уведомления»).
4. Когда пользователь выходит в сеть, сервис доставки автоматически присылает отложенный Push на экран телефона.
5. Если пользователь смахнул Push или пропустил его, при входе в приложение он увидит это уведомление в разделе «Уведомления».

### UC-003. Просмотр и выбор альтернативных вариантов

**Название:** Просмотр и выбор альтернативных вариантов поездки

**Акторы:** Организатор / Участник (только Организатор может выбирать и изменять бронирования).

**Предусловие:**
* Система зафиксировала изменение статуса любого элемента поездки (рейс, отель, активность или трансфер).
* Пользователь открыл приложение, чтобы посмотреть новые варианты.

**Основной сценарий:**
1. Система определяет, какой именно элемент поездки изменился (например, отменился рейс или отель), и запрашивает альтернативы у соответствующего внешнего сервиса.
2. Система фильтрует полученный список по правилам:
   * *Для рейсов:* хватает ли времени на пересадку (с учетом часовых поясов), подходит ли тариф по багажу, нужна ли виза.
   * *Для отелей:* совпадают ли новые даты заселения с измененным планом поездки.
   * *Для активностей:* не пересекается ли новое время с другими событиями в поездке.
3. Система формирует список и показывает пользователям три альтернативных варианта.
4. Организатор просматривает предложенные варианты.
5. Организатор выбирает подходящий вариант.
6. Система обновляет общий план поездки с учетом нового выбора.

**Альтернативный сценарий 1 (Пользователь не нашел подходящего варианта на шаге 3):**
1. Организатор нажимает кнопку «Показать еще варианты».
2. Система высвечивает новый список доступных вариантов.
3. Организатор выбирает подходящий вариант из нового списка.

**Альтернативный сценарий 2 (Вариант просматривает Участник поездки на шаге 4):**
1. Участник заходит на экран с альтернативами.
2. Участник может просматривать предложенные варианты, но кнопка «Выбрать» для него недоступна.
3. Система показывает подсказку: «Только Организатор поездки может изменять бронирования».
4. Участник может отправить Организатору запрос на согласование выбранного варианта.
